# Google Apps Script deployment

`Code.gs` in this directory is the source of truth for the Apps Script web app used by `GOOGLE_SCRIPT_URL`.

## Automatic deployment

Pushes to `master` that change `google-apps-script/**` run `.github/workflows/deploy-google-apps-script.yml`.

The workflow:

1. installs the repository dependencies with `npm ci`;
2. runs the full test suite;
3. creates the local clasp configuration from GitHub Secrets;
4. pushes `Code.gs` and `appsscript.json` to the existing Apps Script project;
5. updates the existing Web App deployment so its URL does not change.

If tests fail, the deployment job does not run.

## One-time setup

### 1. Enable the Apps Script API

Open the Google Apps Script user settings for the Google account that owns the script and enable **Google Apps Script API**.

### 2. Find the Script ID

In the Apps Script editor open **Project Settings** and copy the **Script ID**.

Add it to the GitHub repository as an Actions secret named:

- `APPS_SCRIPT_ID`

The Script ID identifies the project. It is kept in GitHub Secrets so this repository does not need a real `.clasp.json` committed to source control.

### 3. Find the existing Deployment ID

Open **Deploy → Manage deployments**, select the Web App currently used by `GOOGLE_SCRIPT_URL`, and copy its **Deployment ID**.

Add it as:

- `APPS_SCRIPT_DEPLOYMENT_ID`

The workflow updates this deployment instead of creating a new one, so the existing Web App URL remains stable.

### 4. Authorize clasp once

Use clasp `3.4.0`, the same version pinned by CI:

```bash
npx -y @google/clasp@3.4.0 login
```

Complete the Google authorization in the browser. Clasp creates an auth file in your user profile, normally `~/.clasprc.json`.

Copy the **entire JSON contents** of that file into a GitHub Actions secret named:

- `CLASPRC_JSON`

Treat this value like a password. Never commit `.clasprc.json` or paste its contents into source files, issues, logs, or chat.

## Required GitHub Actions secrets

| Secret                      | Purpose                                      |
| --------------------------- | -------------------------------------------- |
| `APPS_SCRIPT_ID`            | Existing Apps Script project ID              |
| `APPS_SCRIPT_DEPLOYMENT_ID` | Existing production Web App deployment ID    |
| `CLASPRC_JSON`              | OAuth credentials generated by `clasp login` |

GitHub location: **Repository Settings → Secrets and variables → Actions → New repository secret**.

## Local clasp usage

For local commands only, copy `.clasp.json.example` to `.clasp.json` and replace the placeholder with the real Script ID. `.clasp.json` is gitignored.

Useful commands from the repository root:

```bash
npm run gas:test
npm run gas:status
npm run gas:push
npm run gas:deploy -- YOUR_DEPLOYMENT_ID
```

`gas:push` changes the Apps Script source but does not by itself guarantee that an existing versioned Web App deployment is using the new source. `gas:deploy` updates that deployment. CI performs both operations automatically.

## Production flow

```text
edit Code.gs
    ↓
commit + push master
    ↓
GitHub Actions
    ↓
npm test
    ↓ pass
clasp push --force
    ↓
clasp update-deployment <existing deployment id>
    ↓
same Web App URL, new code
```

## Manifest

`appsscript.json` is committed with:

- time zone: `Asia/Bangkok`;
- V8 runtime;
- Stackdriver exception logging.

When GitHub Actions deploys, Git becomes the source of truth. Avoid editing production source directly in the Apps Script editor because the next successful Git deployment will overwrite remote source changes.

## Existing one-time data migration

`backupAndMigrateBuyProductDates` remains a manual migration helper. Run it only when the migration is actually required; do not put it in the automatic deployment workflow.

The migration ignores empty values, `-`, and years below 2400.
